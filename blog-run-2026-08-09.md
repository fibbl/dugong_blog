## New post

**Dispatch Nº 103 - "The return that never goes back on the shelf"**
`how-to-automatically-restock-returns-on-shopify.html` · by Priya Singh · 2026-08-09 · 2,660 words · 10 min

Topic: the receiving half of returns, the box that comes back and never makes it to the
shelf. The post covers the restock checkbox as the entire native machinery (selected by
default when inventory is tracked, adds units straight to available at the location that
originally fulfilled the order, no arrival check, no condition step, no memory if skipped,
and the newer returns flow splitting restock from refund so there are two moments to do half
the job); the API layer that records everything and enforces nothing (restock types RETURN,
CANCEL, NO_RESTOCK, deprecated LEGACY_RESTOCK; the doc promise that RETURN adds the quantity
back to the available count); the boundary that Flow's return triggers (Return requested,
approved, declined, closed, processed, reopened) all fire on admin clicks while no trigger
anywhere fires when the return label's tracking hits Delivered; the quality_control and
damaged inventory states the Admin API has carried since August 2023, displayed as
Unavailable, that the native returns flow never touches, plus the documented restock and
shrinkage adjustment reasons; the four deaths of a return (refund with no restock and the
phantom stockout that ends in reordering owned stock; the blind restock that resells a worn
item as new; the restock at the fulfilled-from location while the box sits in another
building, with the fulfillment-service location mismatch erroring in the API; the pile by
the door that exists in no inventory state at all); and the playbook (watch the inbound
label, open a receiving task on the delivered scan, grade in 20 seconds against written
policy, route by grade with location honesty, release the refund on the grade, chase
exceptions, report recovery rate and named shrinkage on Fridays).
